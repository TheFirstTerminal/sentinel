Security

What a security team usually asks before choosing a gateway, answered in one place. If your company has its own questionnaire, send it to support@tft.markets and we'll fill it in.

Your data

Sentinel runs on your servers. Requests, logs, accounts and settings never leave them: there is no telemetry, and the Pro license is checked offline. The only outside requests are the ones you turn on (alerts, log export, automatic HTTPS, IP blocklists) and a once-a-day check on GitHub for a newer version, which UPDATE_CHECK=off turns off. More on the privacy page.

How Sentinel is built

  • Public source. Sentinel Free's code is public on GitHub, so you can read what runs. Pro adds access control on top of the same code.
  • Tested on every change. Every push runs thousands of tests, the OWASP Core Rule Set's own regression suite (3,765 of 3,794 pass), fuzz tests and a test against a running container.
  • Measured honestly. Detection is measured on public data, including a sealed test that Sentinel is never tuned on. The weak spots are published too.
  • Mapped to a standard. Each requirement of OWASP ASVS 4.0.3 that a gateway can cover is mapped to what Sentinel does, including the gaps.
  • Few dependencies. The gateway is one Go program with a short, vendored dependency list.

How releases are protected

  • Every release is built by GitHub Actions from a tagged commit, not on a personal computer.
  • The checksums file is signed (Sigstore), and each release has a software bill of materials (SBOM) and a vulnerability scan. How to check a download yourself.
  • Pro downloads are only handed out for a valid license key, through links that expire after 10 minutes.

Defaults that fail safe

  • New installs start in monitor mode, so nothing legitimate is blocked before you've seen the log.
  • The dashboard needs two-factor authentication for every account, and roles limit who can change what.
  • An unknown or mistyped setting stops the start instead of turning a protection off silently.
  • A request that can't be inspected in time, or a body too large to inspect whole, is refused rather than let through.

Reporting a vulnerability

Report it privately through GitHub's Security tab (Report a vulnerability) or to support@tft.markets. A bypass counts: an attack that protect mode lets through. You get an answer within 3 days, fixes ship in a new release, and you're credited by name in the changelog unless you'd rather not be. There are no cash rewards yet. Full rules: SECURITY.md.

What we don't have yet

We'd rather say it than have you find out. Sentinel has not had an independent penetration test yet; one is planned. The First Terminal has no SOC 2 or ISO 27001 certification. Support is by email, on working days, not around the clock.
